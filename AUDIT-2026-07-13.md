# ICICI-GL Complete Project Audit — 13 July 2026

Scope: `reconciler.py` (1,584 lines, matching engine), `app.py` (568 lines, Flask API + persistence), `templates/index.html` (3,719 lines, UI), `Data/` layout, run configuration. All HIGH findings were verified directly against the source.

Legend: 🔴 High — data loss, mis-matching, or security. 🟠 Medium — correctness/UX/perf under load. 🟡 Low — quality/maintainability.

## A. Matching Engine (`reconciler.py`)

### 🔴 A1. Float equality used for money — silently missed matches
Amounts are stored as `round(amt, 2)` floats and compared with exact `==`, used as `groupby('amount')` and dict keys (`bank_by_amt[target_amt]`) at lines 802, 810, 861, 906, 964, 1075, 1200, 1247, 1275, 1292, 1334 (storage at 436, 639). `round(x, 2)` is not exact in binary, so amounts equal to the paisa can land in different buckets and a valid match is silently dropped. Intermittent and data-dependent — looks like "the engine just misses stuff."
**Fix:** store money as integer paise (`int(round(amt*100))`); key/compare on that integer, keep the float for display only.

### 🔴 A2. Inconsistent amount tolerance between tiers demotes strong matches
Tier 1/2/2.5 use exact-amount dict lookup (line 810); only Tiers 3 and 4 apply the ±0.50 bisect window (915-916, 1020-1021). A UTR match with a 1-paisa difference is invisible to Tier 2 and either surfaces later as a low-confidence date match or is missed entirely. The strongest evidence (matching UTR) is gated behind the strictest amount rule.
**Fix:** apply the ±0.50 (paise-based) tolerance uniformly, especially in the ref/UTR tiers.

### 🔴 A3. GL and Bank dates parsed with different day/month conventions
Bank: `pd.to_datetime(dt_str, dayfirst=True)` (line 428, with a fallback at 430 that *drops* `dayfirst`). GL: `pd.to_datetime(day.findtext('DAY_DT'))` with **no** `dayfirst` (line 628); RTGS likewise (480). For any date with day ≤ 12 (e.g. `03-04-2025`), GL reads 3-Apr while Bank reads 4-Mar — every date-window tier misaligns by up to ~11 months. *(Verified in source.)*
**Fix:** parse both sides with one explicit format / `dayfirst=True`; never let the fallback change convention. Note: if current XML dates happen to be ISO (`YYYY-MM-DD`) this is latent rather than active — confirm against a sample, then still make it explicit.

### 🔴 A4. Cheque extraction false positives feed blind Tier 2.5 matches
`extract_cheque` (196-203) treats the substring `'CH '` as a cheque signal — matching MAR**CH**, BRAN**CH**, PUR**CH**ASE — then grabs *any* 6–10 digit number as the cheque number. Tier 2.5 (825) matches on cheque_no + amount + 3-day window with **no narration check**, so unrelated transactions sharing a coincidental number and amount get auto-matched.
**Fix:** require a word-boundary `CHQ`/`CHEQUE` token, drop `'CH '`, add a narration-compatibility guard to Tier 2.5.

### 🔴 A5. Orphan pruning can permanently delete valid manual links
Lines 727-763: any manual link whose IDs are absent from the currently loaded frames is classified as an orphan and rewritten out of `manual_links.json` (762). A partial data load or a reconcile against the wrong FY folder destroys real user work. No lock, no backup, non-atomic write.
**Fix:** never prune on absence alone; back up before rewrite; atomic write + lock (see B1/B2).

### 🟠 A6. Per-tier `iterrows()` index rebuilds — ~8 full O(N) passes
`bank_by_amt` is rebuilt from `df.iterrows()` in every tier (800, 856, 901, 959, 1006, 1078, 1138, 1196) and the sorted key list re-sorted each time. `iterrows()` is the slowest pandas iteration.
**Fix:** build the amount index once, maintain it as rows get matched; use `itertuples()`.

### 🟠 A7. `compute_duplicates` recomputed 4× per reconcile (+ quick_save)
Lines 711, 1323, 1437, 1525. Regex-heavy `extract_upi_id` re-applied to all rows every call; `apply(axis=1)` for duplicate-matched flags.
**Fix:** compute UPI IDs and dup groupings once at load; refresh only the matched-dependent flag via vectorized `groupby(...).transform('any')`.

### 🟠 A8. Greedy within-tier order: near-UTR steals bank row from exact-UTR
Tier 1/2 (805-845) take the first passing candidate per GL row, treating exact ref-overlap and edit-distance-1 near-UTR equally. An earlier near-match can consume a bank row a later GL row matches exactly.
**Fix:** two passes — exact ref-overlap across all rows first, then near-matches on the remainder.

### 🟠 A9. Un-normalized refs miss genuine overlaps
`extract_serial` zero-pads to 12 digits (193) while `extract_refs` does not (177-185), so `'000123456789'` never intersects `'123456789'` in `has_ref_overlap` (820).
**Fix:** normalize (strip leading zeros or pad consistently, uppercase) before intersection.

### 🟠 A10. GST bundling pre-empts perfect ref matches
`BUNDLED_GST_MATCH` (767-788) runs *before* Tier 1 and consumes rows on amount + narration only.
**Fix:** run high-confidence ref tiers first, bundle the remainder.

### 🟠 A11. GL duplicate-ID suffixes (`_2`) not expanded in manual links
Bank IDs get suffix expansion (732-738, 1451-1458, 1497-1505); GL IDs are used verbatim (741, 1459, 1508). A manual link on a base gl_id silently fails to cover its duplicates.
**Fix:** apply the same `startswith(base + '_')` expansion to gl_ids; extract one shared `expand_ids()` helper (logic is currently copy-pasted in 3 places).

### 🟠 A12. Bank sign defaults to CREDIT for anything not exactly 'DR'
Line 437: missing/renamed/NaN `Cr/Dr` column ⇒ every row CREDIT ⇒ the sign-sensitivity guard inverts systematically.
**Fix:** validate the column; log + skip unknown values instead of defaulting.

### 🟠 A13. Other engine mediums
- **Near-UTR (edit-distance 1) without narration check** can auto-match different RTGS transfers (127-136, 823) — require narration compatibility for near-matches.
- **Tier 6 one-to-many** requires identical narration and full-group sum; real splits with differing narrations or partial subsets are missed (1240-1266). **Tier 6b** takes `cands.iloc[0]` instead of the best candidate (1279).
- **Bare `except:`** swallows whole RTGS/CMS files on parse errors (429, 481, 493, 515, 719, 764) — log file + row, surface skip counts in DQ stats.
- **No `encoding=` on `read_csv`** (417, 513-514); Indian bank exports are frequently cp1252 — a decode error silently skips the file. JSON writes also lack `encoding='utf-8'`.
- **`detect_type` substring tags**: `INF`, `MAT`, `TOP`, `CMS` etc. matched as substrings (138-145) → bogus tags in DQ output. Use word boundaries.
- **UTR conflict guard** runs on pre-tokenized words (226-230) so UTRs embedded in tokens like `TR642723737765` are invisible to it — run the 12-digit extraction on the raw string as `extract_refs` does.
- **Magic branch-specific literals** (`ICICI BANK THALASSERY`, `KOD/PKT/KTH`, Onam keywords, `SL-758`, Mar-31→May-29/30 dates, Malayalam triggers) hardcoded in tiers (97, 105, 854, 957, 1067, 1073, 1191) — move to a config block.

### 🟡 A14. Engine structure
`reconcile()` is ~750 lines with ~10 near-identical tier blocks differing only in date window, tolerance, predicate, and label. Parameterize one `run_tier(status, date_window, amt_tol, predicate, confidence)` helper — removes hundreds of lines and eliminates the per-tier divergences above at the root. `quick_save`'s fallback (1573) also drops `global_upi_registry` and `progress_cb` — forward all args.

## B. Backend & Persistence (`app.py`)

### 🔴 B1. `except: pass` on manual-links load can wipe all manual matches
Verified at app.py:321-340: if `manual_links.json` exists but fails to parse, `matches` stays `[]` and the subsequent `json.dump` **overwrites the file with only the new match** — the entire manual-reconciliation history is silently destroyed. Same swallow pattern at lines 42, 52, 83, 218, 368, 384, 497.
**Fix:** distinguish "absent" (start empty) from "unparseable" (abort with 500, preserve file). Add logging — app.py currently imports no logger at all.

### 🔴 B2. Non-atomic writes, and no lock on anything except sticky notes
Only `sticky_notes.json` has a mutex (474). Manual-match append (339), unlink rewrite (419/465), alias write (390), and both `data.json` writers in reconciler (1420, 1568) are unlocked read-modify-write with `open('w')` truncate-in-place. Two tabs / a double-click / the debug reloader can interleave and lose writes; a crash mid-write corrupts the file (which then triggers B1).
**Fix:** one shared `save_json(path, obj)` helper — per-file `threading.Lock`, write to `.tmp`, `fsync`, `os.replace()`, keep a rotating `.bak`. This single helper closes B1+B2+A5 together.

### 🔴 B3. Path traversal via unvalidated `fy` parameter
Verified: `get_fy_path` (100-101) is a raw `os.path.join(DATA_ROOT_DIR, fy)`; `fy` comes from client JSON via `/api/set-fy` (173-179) with no whitelist. `save_sticky_note` then does `os.makedirs` + file write under that path — arbitrary directory creation and file write outside `Data\`.
**Fix:** validate `fy` against `list_fys()` output in `set_fy` and re-check in `get_fy_path`.

### 🔴 B4. `debug=True` — Werkzeug console is remote code execution
Verified at app.py:568; `start_flask.bat` also sets `FLASK_ENV=development`. Any unhandled exception exposes an interactive Python console to whoever can reach port 5000. Also doubles the process via the reloader, worsening B2 races. `secret_key` is a hardcoded constant (line 11), making the session (which carries `fy`, see B3) forgeable.
**Fix:** `debug=False` (gate behind env var), remove `FLASK_ENV=development`, generate the secret key. For real use, serve via `waitress-serve --threads=8 app:app`.

### 🟠 B5. `data.json` cache can silently disagree with `manual_links.json`
`get_data` (262-268) returns `data.json` blindly if present; nothing ties it to the `manual_links.json` content it was built from. Hand-edits or a half-completed write leave users viewing results that no longer reflect their links, with no signal.
**Fix:** stamp `data.json` with the manual-links hash/mtime; on mismatch trigger quick_save or flag "recompute needed."

### 🟠 B6. Payload & API design
- `/api/data` ships the full blob — currently **9.6 MB** for FY2025-26 — uncompressed, no ETag, and every manual match round-trips the whole thing. Add `flask-compress` (one-liner, ~10× smaller) + ETag/304.
- `__ALL__` aggregation (187-257) deep-copies every row of every FY in-request and will run a full synchronous `reconcile` if any FY lacks its cache — a page load becomes a multi-minute stall.
- SSE `progress_stream` (140-146) is `while True` with no termination or disconnect check, on a single *global* PROGRESS dict — each browser tab holds a worker thread forever.
- Missing input validation: `request.json` unchecked (175, 312, 412, 530) → non-JSON bodies produce raw 500s; `str(e)` leaked to clients (400, 471, 561).
- Inconsistent response shapes (`{status,message}` vs full data blob vs `{status,notes}`); "already_exists" returns 200.

### 🟠 B7. Alias-learning can poison matching globally
A single 1:1 manual match with similarity > 0.4 writes a permanent **global** alias (342-391) affecting all FYs, with no UI to review or delete learned aliases.
**Fix:** raise the threshold, scope per-FY or require confirmation, add a review/delete endpoint.

### 🟡 B8. Backend lows
- `index()` (124-134) clears the global CACHE on every root hit — a stray refresh forces disk re-loads for all FYs.
- Root `data.json` cleanup only runs under `python app.py`, but `start_flask.bat` uses `flask run` — the guard never fires via the documented launch path.
- app.py hardcodes persistence paths while `reconciler.get_paths()` already exists — reuse it; share `load/save_manual_links` helpers (the app-layer dedup at 328 is unaware of suffix expansion).
- CACHE never evicts (memory grows per FY visited); `get_cached_data` copies full frames per call.
- No undo, no manual-links export/import, no CSV export endpoint, no health check.
- No backup strategy for the JSON state — the highest-value, least-recreatable data in the system (also not in git).

## C. Frontend (`templates/index.html`)

### 🔴 C1. `showToast()` called 7×, never defined — ReferenceError
Verified: calls at 2515, 2756, 2766, 2849, 2934, 2945, 3551; no definition exists. Every read-only-mode guard in the All-FYs view throws — the user gets no feedback, just a console error.
**Fix:** implement a small toast helper (trivial).

### 🔴 C2. `checkCurrentFy()` defined but never called — session lost on reload
Verified: defined at 1804, never invoked; `DOMContentLoaded` only calls `fetchFys()`. A page refresh always drops back to the splash screen even with an active FY session.
**Fix:** call it in `DOMContentLoaded` (one line).

### 🔴 C3. Unescaped transaction data interpolated into HTML and `onclick` strings
Narration into `innerHTML` (2207) and into inline `onclick` handlers with only single-quote escaping (2205, 2102-2129, 2137-2139). Bank narration free-text containing `</div>`, a double quote, or backslash breaks rendering — and is a stored-XSS vector (server stores notes/narrations verbatim; app.py:532 does no sanitization either).
**Fix:** HTML-escape all interpolated values; move click payloads to `data-*` attributes with delegated listeners.

### 🟠 C4. Render pipeline does full O(n log n) work per keystroke
`render()` (2553-2725) re-filters and re-sorts the *entire* dataset on every keystroke, checkbox, selection, and 20-row scroll increment. `getAllBankItems`/`getAllGLItems` (2538-2551) spread-clone all rows per call and are independently rebuilt in 5–6 places (render, updateTally, updateDQStats, renderNotesHub, editStickyNote). The scroll model is load-more, not virtual — deep scrolling accumulates unbounded DOM.
**Fix (in order of leverage):**
1. Build combined arrays + an id→item Map **once** after data load; set `matched` in place; reuse everywhere.
2. Debounce search/amount inputs (~200 ms).
3. Cache filtered+sorted arrays keyed by filter signature; selection changes toggle `classList` on the affected card instead of full re-render.
4. Precompute numeric `dateTs` per row so sorting stops re-parsing date strings.
5. (Later) true fixed-window virtual scrolling.

### 🟠 C5. UX gaps
- No in-flight guard on `commitMatch`/`quickReconcile`/`saveStickyNote` — double-click or double Ctrl+Enter fires duplicate `/api/manual-match` posts.
- Network failure = blank screen: `fetchData` catch hides the overlay with no error UI; `commitMatch`/`selectFy` have no catch at all.
- Amount badge desyncs when Min/Max inputs are hand-edited (badge still shows the old quick-filter value).
- Tab key hijacked for panel-switching (3668-3675) — keyboard users can't reach toolbar buttons; use a different key.
- ArrowDown navigation stops at the load-more boundary (3659) — bump the limit when nav hits the last loaded row.

### 🟠 C6. Missing features that would clearly pay off
- **Export** of the reconciliation report (matched/unmatched CSV/Excel) — a core deliverable for bank recon; the dashboard is view-only today.
- **Undo toast** after a manual match (currently: find row → open modal → unlink).
- **Bulk actions**: select-all-visible, shift-range select, "match all CRITICAL-confidence suggestions."
- In-flight spinner on commit (the post-match render hitch reads as a freeze).
- Persist filter state to localStorage.

### 🟡 C7. Frontend lows
- Duplicated logic: fiscal-month preset mapping in 4 places; 4 near-identical partner-select helpers; mirrored footer-helper branches — extract `getPresetMonths()` and side-parameterized helpers.
- Dead code: popover re-init loop every render with zero popover elements (2720-2724); `.dashboard-strip`/`.stat-card` CSS never used; `.animate-fade-in` used ~10× but never defined; duplicate conflicting `.stat-label`/`.stat-value` blocks (601 vs 1012).
- `!important` overuse across tag/badge/modal/flatpickr rules causes specificity wars (e.g. hover bg fighting selected state).
- Accessibility: clickable `div`s without `role`/keyboard activation; cards lack `aria-selected`; dark scrollbar thumb (#334155) on the light theme.

## D. Recommended fix order

> **Status (July 13, 2026):** Phases 1 and 2 plus quick wins 11 and item C3 are **DONE and verified** (see `storage.py`, updated `app.py`/`reconciler.py`/`index.html`/`start_flask.bat`). Phases 3–5 and the remaining Phase 4 items are open.

2. Safe manual-links load: never overwrite on parse failure (B1). Add logging to app.py.
3. Stop orphan-pruning manual links on absence alone (A5).

**Phase 2 — close security holes (minutes each):** ✅ DONE (incl. item 6, HTML escaping)
4. Validate `fy` against `list_fys()` (B3).
5. `debug=False`, remove `FLASK_ENV=development`, env-based secret key (B4).

**Phase 3 — matching correctness (the audit's biggest recon-quality wins):**

8. Consistent `dayfirst` date parsing everywhere (A3).
9. Cheque extraction word-boundary fix + Tier 2.5 narration guard (A4).
10. Exact-ref-first two-pass matching; ref normalization; GL suffix expansion in manual links (A8, A9, A11).

**Phase 5 — structural (larger refactors, best done after the above):**
